# 问题审核台账

> 目的：把"文档之间、文档与题面之间、公式与文字之间"的**自相矛盾**逐条揪出来、留痕、修正。
> 一条矛盾如果只靠"读一遍"是抓不住的，必须按下面的维度逐类扫描。**每轮审核都在本表追加，不覆盖历史。**

建立日期：2026-09-12

---

## 一、审核维度（每轮按这七类扫）

| # | 类别 | 典型形态 | 怎么扫 |
|---|---|---|---|
| **D1** | **公式方向/量纲矛盾** | 同一个量在不同文件里一个乘 $\eta$、一个除 $\eta$；单位一个 kWh 一个 kW | 对同一符号全局 grep，逐处比方向与量纲 |
| **D2** | **决策与正文矛盾** | 决策台账已改为 X，正文仍写 Y（旧口径残留） | 台账每条决策 → 反查所有引用处 |
| **D3** | **数值锚点过期** | 旧口径算出的数字仍被当"标尺"用 | grep 关键数字，确认其口径与天数 |
| **D4** | **符号未定义** | 公式里出现的量在全文找不到定义（如 $\hat N_{d\mid\tau}$） | 逐个符号反查定义 |
| **D5** | **信息集/因果矛盾** | 计划阶段引用了当天实际数据；某子问越级使用了不该用的附件 | 检查每个模块的输入清单 |
| **D6** | **编号与题面不符** | 表1/表2/表3 的所指与题面不一致 | 与 `C题.pdf` 逐表对照 |
| **D7** | **可实施性缺陷** | 方法依赖不存在的数据（如"去年同期"，而附件2 只有 2025 一年） | 对每个数据需求问"这份数据真的存在吗" |

## 四、审核与 git 留痕的对应

每次修正**必须**产生一条 git 提交，提交信息包含审核编号，便于论文写作时追溯：

```
审核 R-01: Q4 终端续存系数方向更正 1/η → η_d

问题：开工包式(50) 除 η，与台账第 1 项乘 η_d 相反
依据：E 为储电量，期末多存 1 kWh 可交付 η_d kWh，故价值 = η_d·c
影响：原式高估库存价值 1/η²≈1.23 倍，会系统性多留电
处理：式(50) 改为 v_τ = η_d · mean(c_ω)；AGENTS 台账 #16 留痕
```

**论文写作时**：§「模型的分析和检验」可写一节"模型的自洽性检查"，把 R-01、R-08、R-09 这三条
（口径方向、结论的可实现性、对照的可归因性）作为**模型检验过程**写出来——这比只报一个结果更有说服力。
